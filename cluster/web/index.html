A distributed key-value store where every write is agreed on by a majority via Raft. Kill nodes or cut them off from the network: the cluster re-elects a leader and never loses a committed write.

Concurrent clients over real HTTP. Every write is fsynced to a majority's WAL before the reply. Try killing the leader mid-run.

Try this

  1. Kill the leader. A follower times out and wins an election in a few hundred ms.
  2. Write a key while it's down. Two of three nodes is still a majority.
  3. Start it again. It replays its WAL from disk and catches up from the new leader.
  4. Partition the leader. It can't reach a majority, so it steps down. No split-brain.
  5. Kill two nodes. Writes stall rather than return wrong data. Consistency over availability.
